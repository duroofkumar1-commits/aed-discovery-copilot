# AED Discovery Copilot

**Hackathon theme:** AI for Intelligent AED Accessibility — Singapore
**Lane:** Lane 1, Discovery & routing
**Status:** working prototype, built with a development-only sample
dataset — see [`docs/DATA_MANIFEST.md`](docs/DATA_MANIFEST.md) before
using this for judging.

> **Prototype for planning and simulation only — not for emergency use.**
> In an emergency in Singapore, call **995** immediately and follow SCDF
> instructions. Use official SCDF / myResponder channels.

---

## What this is

A decision-support prototype that, given a location, day, and time,
ranks nearby public-access AEDs — going beyond a plain "nearest pin" by:

1. estimating **walking** distance instead of straight-line distance
   (documented as an estimate, not a routed path — see the method card),
2. **parsing operating-hours text** to flag whether each AED is likely
   open, likely closed, or unknown at the query time, and
3. **abstaining** (`UNKNOWN_HOURS`) instead of guessing when the hours
   text can't be parsed.

It is evaluated against the challenge's required minimum baseline
(nearest AED by straight-line distance, hours-blind) — see the
headline numbers below.

**Intended user:** community planners, facility/registry managers,
researchers, and emergency-preparedness educators exploring AED
coverage — not the general public in a real emergency, and not SCDF
dispatch.

## Quickstart

```bash
git clone <this-repo>
cd aed-discovery-copilot

# 1. (Re)generate the development dataset (optional — already included)
python3 src/generate_dataset.py

# 2. Run the evaluation (baseline vs. improved ranker)
python3 src/evaluate.py
# -> prints and writes docs/EVALUATION_REPORT.md

# 3. Run the interactive map demo
python3 -m http.server 8000
# then open http://localhost:8000/web/index.html
```

No API keys, no build step, no third-party services beyond a public,
keyless OpenStreetMap/CARTO tile layer used purely for map rendering
(not part of the evaluated data or logic).

## Headline evaluation result

Full report: [`docs/EVALUATION_REPORT.md`](docs/EVALUATION_REPORT.md)
(regenerated by `src/evaluate.py`; numbers below are from the last run
against the 185-record development sample, 200 synthetic scenarios).

| Metric | Baseline | Improved ranker |
|---|---|---|
| False-open rate at top-1 | 36.0% | **0.0%** |
| Top-5 feasible-AED recall | 83.0% | **100.0%** |
| Abstains instead of guessing | never | 0.0% on this sample (see report for why) |

This is a **simulation**: "open"/"closed" ground truth comes from
parsing the dataset's own operating-hours text, not verified real-world
device status. It measures whether hours-awareness helps internally
versus a blind-distance baseline — see the report for the full caveat
and reasoning.

## Repository layout

```
data/aed_sample.geojson     development dataset — 13 real + synthetic (see DATA_MANIFEST)
src/generate_dataset.py     builds data/aed_sample.geojson
src/utils.py                haversine distance + operating-hours parser
src/baseline.py             required baseline: nearest by straight-line distance
src/ranker.py                improved ranker: walking-distance proxy + hours-awareness
src/evaluate.py             synthetic evaluation harness -> docs/EVALUATION_REPORT.md
web/                        static Leaflet map demo (index.html, app.js, style.css)
docs/DATA_MANIFEST.md       what's real vs. synthetic, licensing, citation
docs/METHOD_CARD.md         architecture, assumptions, honest limitations
docs/SAFETY_STATEMENT.md    mandatory safety-gate checklist
docs/EVALUATION_REPORT.md   generated by src/evaluate.py
```
